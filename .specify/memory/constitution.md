# CDC Badge Development Constitution

This repository is the trivial-to-start environment for building, flashing and
debugging Rust WebAssembly plugins for the CDC Badge. It is a teaching repo for
students trying classical, vibe-coding and spec-driven development. It contains
no firmware; the firmware and plugin SDK are vendored read-only under `vendor/`.

## Core Principles

### I. Trivial Onboarding
Getting from a bare computer to a built, tested plugin MUST stay trivial: one
documented setup action (`python scripts/setup.py`), no manual per-dependency
installation, opinionated defaults, and an editor that surfaces the actions.
`EASY.md` MUST cover absolute beginners, including installing VS Code, git and
Python per OS.

### II. Plugin Scope Only
This repo builds plugins, not firmware. No firmware (C++/ESP-IDF) build is in
scope. Upstream firmware and SDK are consumed as updatable git submodules;
`host_api.h` is canonical upstream and is never forked or edited here.

### III. Cross-Platform, Windows-First-Class
Windows is the majority target and is verified by a CI matrix (windows/macos/
ubuntu), not by hand. Tooling is implemented in cross-platform Python; no
PowerShell is authored (at most a one-line delegating wrapper). Use only
officially cross-platform tools (rustup, Python, pyserial, Binaryen).

### IV. Test-Driven Development
Automated tests are standard. Plugin logic is host-testable (`cargo test` via
`badge test`); write tests first, keep them green. SDD-generated features
include test tasks by default. CI runs build + test on every change.

### V. Code Quality & Beginner Clarity
Generated and reviewed code follows `code-quality.md` (DRY, KISS, single
responsibility, clear names, no magic numbers, error handling). Because the
audience is learners, code generated by the assistant is commented generously to
explain what it does. Agents actively guard against the common AI-agent mistakes
documented in `code-quality.md` (hallucinated APIs, security issues,
overcomplication, ignoring patterns, unverified output).

### VI. Tool-Agnostic
The AI assistance works in Claude Code, Codex and opencode. A single skill and a
single `AGENTS.md` serve all three; per-agent files are committed so everything
is active on first open with no interactive selection.

## Governance
This constitution governs the onboarding repo. Documentation describes the
current state only (no history, rationale, or migration notes). Changes keep the
host API consumed read-only and the cross-platform CI green.
